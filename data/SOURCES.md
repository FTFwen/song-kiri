## 采集方式（2026-10-19 更新）

### 1. 拿到 UP 主名下**全部**投稿

⚠️ **两条旧路都已废**：

- `https://api.bilibili.com/x/space/arc/search?mid=...` —— 会对本机 IP 连续返回
  `code=-799 请求过于频繁`，再试几次直接 `code=-412 request was banned`。
- `https://api.bilibili.com/x/polymer/web-dynamic/v1/feed/space?host_mid=<mid>` —— 曾经稳定可用
  （当初就是靠它翻完 `退烧药777` 的 **93 条投稿**，覆盖 2026-08-21 → 2026-10-11；
  `item.modules.module_dynamic.major.archive` 拿 `bvid`/`title`，`item.modules.module_author.pub_ts`
  是 **UTC 秒**、写进 `publishedAt` 要 **+8 小时**），但 **2026-10-12 晚起对「所有 mid」都返回 HTTP 412**，
  连原先能用的 `141266664` 也一起 412，**不再是可用路径**（2026-10-19 依旧是 412）。

**现在最可靠的是 UP 主的空间页**（2026-10-19 实测）：

```
https://space.bilibili.com/141266664/video
```

- 用真浏览器打开（本机用 `bsk`，见 `AGENTS.md` 第 12.7 节），列表里直接有**标题 + 时长**，比搜索接口权威得多。
- ⚠️ 它的 HTML 里**没有**内嵌数据（`__INITIAL_STATE__` 不存在），`Invoke-WebRequest` 直接抓是空的，**必须渲染**。
- 页面顶部会显示「视频 N」与「投稿 M」两个数，和上次记的数一比就知道有没有新东西。

**备用路线：搜索接口**（2026-10-12 晚实测完全可用，10-19 也可用）：

```
GET https://api.bilibili.com/x/web-interface/search/type?search_type=video&keyword=<关键词>&order=<pubdate|click>&page=<页号>
```

- 返回 `code=0`，每页 20 条；`data.result[]` 里有 `bvid` / `author` / `mid` / `title`（含 `<em>` 高亮标签要剥掉）/ `duration` / `pubdate` / `description`。
- 带 `User-Agent` + `Referer: https://search.bilibili.com/` 即可，**不需要 cookie 或 wbi 签名**（带 wbi 的 `wbi/search/type` 结果完全一样）。
- 关键词要多换几个（`冬雾kiri` / `冬雾kiri歌切` / `冬雾_kiri` / `雾歌` / 各切片man 的名字 …），每种关键词都要把 `pubdate` 与 `click` 两种排序各跑一遍——只靠一个关键词会漏。
- ⚠️ **412 是本机 IP 级、间歇性的**：一口气跑多个关键词会中途开始 412，必须退避重试（8s / 16s / 24s 递增）。**412 不代表参数写错了。**
- ⚠️ 有时接口会**直接返回 HTML 而不是 JSON**（响应体以 `<!DOCTYPE` 开头），这也是限流的一种表现，重试即可。
- ❌ `x/web-interface/search/all/v2` 虽然也返回 `code=0`，但 `data.result[]` 里的字段全是 `undefined`，不可用。
- ❌ 直接抓 `search.bilibili.com` 的 HTML 也不可靠：数据被压缩成变量引用（`bvid:cG`）。
- 2026-10-12 晚用这套办法收集了 **474 个 BV**（13 个关键词 × 2 种排序 × 多页，见 `.dsh-tmp/search-raw.json`），
  逐个 `view/detail` 回源后**只多出一首新歌《屑屑》**——绝大多数命中都是重复版本，详见下面的「切片man 生态」。

- ⚠️ 另一个投稿人 `冬雾_kiri`（mid `3707024510552805`，主播本人）**依然没法用接口枚举**：她的 mid 走动态流返回 412，
  走搜索也只能捞到已被收录的 `BV1bTYx6gEqU` 那一条。只能人工看 `https://space.bilibili.com/3707024510552805/video`
  （2026-10-19 用 `bsk` 打开过：视频 13 条，最新的歌仍是 2026-09-09 的 `BV1bTYx6gEqU`，此后新增的都是 ASMR / 图文），
  再逐条 `view/detail` 核实归属与曲名。

### 1.5 切片man 生态（同日主播的切片不止一家）

### 2. 判定曲名

⚠️ **`x/web-interface/view` 现在不再返回 `data.tags`（是 `null`）**，要改用：

```
GET https://api.bilibili.com/x/web-interface/view/detail?bvid=<BV>
```

曲名在 `data.Tags[]` 里，取 `tag_type === "bgm"` 的那条，去掉 `发现《` `》` 外壳即可。
同时 `data.View` 里有 `owner.mid` / `title` / `pubdate` / `duration` / `pic`。

判定不出来就**问用户**，不要猜。

### 3. 下载素材

```
node tools/fetch-media.mjs          # 只补缺失的
node tools/fetch-media.mjs --check  # 只体检
node tools/fetch-media.mjs --force  # 全部重下
```

内部流程：`x/web-interface/view` 核 `owner.mid`（**必须命中 `ALLOWED_UPLOADERS` 白名单**，否则报「归属不符」并拒绝下载）→ `x/player/playurl?fnval=16&qn=64` 取 `dash.audio` 里
`bandwidth` 最大的一条 → 音频存 `media/<BV>.m4a`，封面（`data.pic`）存 `media/covers/<BV>.jpg`。

### 4. 重建页面数据

```
node tools/build-data.mjs
```

重建 `data/kiri/*.json` 与 `js/data.js`，并把上面抄回来的 `source*` 字段映射进页面真正读取的运行时数据里。

注意事项：

- 请求之间至少间隔 **1 秒**，否则会碰到 `HTTP Error 412`。
- 必须带 `User-Agent` 和 `Referer: https://www.bilibili.com/`。
- **B 站音频直链带签名、会过期，绝不能写进 `songs.json` 或提交进仓库。**
- **下载好的素材也不提交**：`media/` 已加入 `.gitignore`，历史里同样不含素材。只提交 `songs.json` 与本文档。
