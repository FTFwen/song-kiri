## 采集方式（2026-10-12 更新）

### 1. 拿到 UP 主名下**全部**投稿

⚠️ **旧路已废**：`https://api.bilibili.com/x/space/arc/search?mid=...` 现在会对本机 IP 连续返回
`code=-799 请求过于频繁`，再试几次直接 `code=-412 request was banned`。**不要再依赖这个接口。**

现在走**动态流**，已验证稳定，能翻完整个投稿历史：

```
GET https://api.bilibili.com/x/polymer/web-dynamic/v1/feed/space?host_mid=141266664&offset=<上一页的 offset>
```

- 响应 `data.items[]`，视频投稿在 `item.modules.module_dynamic.major.archive`（`bvid` / `title` / `duration_text`）。
- `item.modules.module_author.pub_ts` 是 **UTC 秒**，写进 `songs.json` 的 `publishedAt` 要 **+8 小时**。
- 用 `data.has_more` 与 `data.offset` 翻页，每页之间间隔 1 秒以上。
- 2002 年以前的？没有——本站 UP 主共 **93 条投稿**，覆盖 2026-08-21 → 2026-10-11。

辅助接口（都能用）：`x/space/upstat`（只有播放数）、`x/polymer/web-space/seasons_series_list`（本站返回空，没有合集）。

### 2. 判定曲名

⚠️ **`x/web-interface/view` 现在不再返回 `data.tags`（是 `null`）**，要改用：

```
GET https://api.bilibili.com/x/web-interface/view/detail?bvid=<BV>
```

曲名在 `data.Tags[]` 里，取 `tag_type === "bgm"` 的那条，去掉 `发现《` `》` 外壳即可。
同时 `data.View` 里有 `owner.mid` / `title` / `pubdate` / `duration` / `pic`。

判定不出来就**问用户**，不要猜。

### 3. 下载素材

```
node tools/fetch-media.mjs          # 只补缺失的
node tools/fetch-media.mjs --check  # 只体检
node tools/fetch-media.mjs --force  # 全部重下
```

内部流程：`x/web-interface/view` 核 `owner.mid` → `x/player/playurl?fnval=16&qn=64` 取 `dash.audio` 里
`bandwidth` 最大的一条 → 音频存 `media/<BV>.m4a`，封面（`data.pic`）存 `media/covers/<BV>.jpg`。

### 4. 重建页面数据

```
node tools/build-data.mjs
```

重建 `data/kiri/*.json` 与 `js/data.js`，并把上面抄回来的 `source*` 字段映射进页面真正读取的运行时数据里。

注意事项：

- 请求之间至少间隔 **1 秒**，否则会碰到 `HTTP Error 412`。
- 必须带 `User-Agent` 和 `Referer: https://www.bilibili.com/`。
- **B 站音频直链带签名、会过期，绝不能写进 `songs.json` 或提交进仓库。**
- **下载好的素材也不提交**：`media/` 已加入 `.gitignore`，历史里同样不含素材。只提交 `songs.json` 与本文档。
